# Drawspeak native v1 — UX review (Sol)

Date: 2026-11-04. Scope: supplied iPad Pro 13-inch simulator captures, requirements and source inspection. No app interaction, builds, tests, pairing, sends, provider calls, code changes or commits were performed for this review.

## Verdict and method

The canvas communicates the central comparison model well, and the implementation has the required two-action feedback structure. The complete review loop still has blockers: interactive HTML cannot be exercised from the canvas, and a library read failure is presented as a fresh library. Serious friction also comes from oversized source previews hiding the comment and scope controls, draft resumption changing the reviewed content, and recovery paths that require leaving the task without an actionable handoff.

Target user: the owner reviewing UI from T3 Code on their own iPad, sometimes rushed, using Pencil and speech. User outcome: deliver one accurate package to the intended thread and compare returned alternatives without losing source context. There is no conversion objective; every recommendation below serves completion, control or confidence.

Method: read `/Users/rafalw/.claude/skills/uxled-psychology/SKILL.md` plus its `references/principles.md`, `references/playbooks.md`, and `references/audit-and-ethics.md`. Applied the four lenses and canonical principle names. Severity follows this task: **P0 blocks a flow; P1 serious friction/misleading; P2 polish**. Source-derived branches are findings from inspection, not claims of reproduced failures.

Requirements read in full: `docs/PRD.md`, ADR-0001 through ADR-0007, and `docs/DESIGN-V2.md`. ADR-0007 resolves BYOK and text-bundle Pull for this build: direct ElevenLabs key entry and lack of binary PNG download are consequently not counted as defects. The older implementation-status section in PRD §12 is not evidence of the current native implementation.

## What works well

- Now, Proposal A and Proposal B remain visibly adjacent in light and dark appearances; source screenshots keep their original colors (**Juxtaposition**, **Mental Model**).
- Floating palettes preserve the canvas as the main workspace; Comments, History and Settings appear on demand (**Progressive Disclosure**).
- Numbered pins correspond to the Comments list; the list exposes actual comment text and readiness (`light-notes.png`) (**Recognition Over Recall**).
- Feedback opens directly to preview with Send to Agent and Save Draft; source has persistent result states and Back to Canvas, without a post-Send confirmation (**Feedforward**, **Peak-End Rule**).
- Settings explain auto-voice, finger navigation, ElevenLabs upload and billing; pairing explains revocation and leads to a searchable project/thread list (`light-settings.png`, `light-threads.png`, `ds-pair.png`) (**Feedforward**, **Discoverability**).

## Flow walkthrough and predicted emotional journey

These scores are heuristic predictions, not research results: −2 blocked/anxious, −1 friction, 0 neutral, +1 confident, +2 value realized.

1. **First launch → import → mark → voice → autosave:** source-backed empty state offers Import before pairing (+1). First import skips target selection; markup opens the inspector and auto-voice is ON (+1). The source image consumes the inspector viewport, hiding text and Saved feedback (−1). Permission denial followed by a Type Instead action that only dismisses the warning is the worst visible interaction gap (−2 for a novice unable to find typing). The intended peak is the first saved, numbered spoken comment (+2); simulator captures do not establish that peak occurred.
2. **Feedback → preview → action → result:** one tap opens preview (+1), but the initial viewport omits the comment and inclusion control (−1). Source supports a second tap to send or save, with no extra confirmation, followed by a durable result (+1). In the supplied unbound state, Save Draft remains available; Send needs setup. No successful send/result capture is supplied.
3. **Pair → bind:** instructions identify where to obtain the code (0); the access choice needs more deliberation (−1). The real post-pairing screenshot reaches a searchable thread picker (+1). Choosing a row binds/dismisses in source (+1); the screenshot does not show that ending. Pairing and binding are separate states, as they should be.
4. **Pull → compare:** Pull is hidden under Add (−1), then Fit All and adjacent lanes support recognition (+1). Missing visible change summaries and automatic selection of a pulled baseline undermine confidence (−1). Trying to exercise a returned prototype is blocked by non-interactive canvas content (−2). This is the main product-value blocker.
5. **Recovery:** mic-denied and offline-transcription copy preserve a text path/audio in source (+1), but the typing handoff is incomplete (−1). Delivery Unknown offers Check Thread before resend (+1). Reconnection requires rediscovering setup (−1). A library load error becomes an unexplained empty library (−2), the most severe trust failure. The desired ending is restored local work plus a deliberate Ready to Send action, never automatic execution.

## Two-tap contract: assessment

- **Structural pass by source inspection:** `FeedbackPreviewSheet.swift:52` calls `model.send()` directly; line 55 calls save directly. Neither path opens a mode picker or confirmation. `FeedbackPreviewModel.swift:64` freezes a batch ID/payload for send; save records a local draft and checks the durable-save error before showing Draft Saved.
- **Result structure exists:** Sent includes recipient/count/time; ACK is distinguished from agent work; Draft Saved says nothing was sent; both offer Back to Canvas. Sent and drafts remain in History. These are source findings, not captured/live acceptance.
- **Qualification:** exactly two taps assumes ready notes and a connected, bound canvas. The supplied unbound screenshots do not fail that count by disabling Send. F05 makes preview reviewable, and F12 supplies initial setup without adding a confirmation to ordinary sending.
- **Unknown/offline protection exists:** Delivery Unknown exposes Check Thread, not blind Retry; core reconciliation searches `drawspeak-batch:<id>` before moving to Ready to Send (`Workspace.swift:723`). Restart/reconnect do not call deliver automatically (`Workspace.swift:645`). Do not replace this with automatic resend to reduce friction.
